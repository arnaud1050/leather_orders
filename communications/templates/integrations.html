Email sync

These apply to every mailbox this company has connected. "How far back to read" only affects a mailbox's first sync — after that each run picks up where the last one finished.

{# Says which half of the settings this form owns. An unticked checkbox posts nothing, so without it the calendar form below would read every box here as "off" and switch them all off on save. #}

With "keep mail from unknown senders" off, the app stores only conversations it can tie to a client already on file and discards the rest. With it on, unmatched mail collects in Leads, where it can be turned into a client.

"Sync mail automatically" is the master switch for both sections — with it off, neither mail nor the calendar is fetched on a schedule, whatever the intervals say.

Automatic handling

Rules for senders whose mail never needs a decision. They apply to new conversations only — adding one doesn't reach back through mail already in Leads. Enter a full address, or a domain (@example.com) to cover everything from it; an exact address wins over a domain rule.

Always hide

Newsletters, suppliers, receipts — anything that would otherwise pile up in the lead inbox. Hidden conversations are kept and can be restored from the dismissed view; unlike hiding one by hand, a sender covered by a rule stays hidden when they write again.

Security

Access tokens are encrypted before they're written to the database, and the key that decrypts them is held in the environment rather than alongside the data. Disconnecting revokes the grant at Google.

{% if using_derived_key %}

Tokens are being encrypted with a key derived from SECRET_KEY, the development fallback. Set COMMS_ENCRYPTION_KEY before connecting a real mailbox — otherwise changing SECRET_KEY makes every stored token unreadable and each account has to be reconnected.

{% endif %}
